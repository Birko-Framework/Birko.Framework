# wiki-snippets

Compiles the C# in the [wiki](https://github.com/Birko-Framework/Birko.Framework/wiki), so the guide
cannot quietly stop matching the framework — the drift that made `PREZENTACIA.md` unusable.

Run by `.github/workflows/wiki-snippets.yml`: on pushes that touch `Birko.*`, nightly (the wiki is a
separate repo and changes without touching this one), and on demand.

## Locally

```
git clone https://github.com/Birko-Framework/Birko.Framework.wiki.git /tmp/wiki
python ci/wiki-snippets/extract.py /tmp/wiki ci/wiki-snippets
dotnet build ci/wiki-snippets/snippets.csproj
```

`Imports.props` is generated by the workflow from the Birko.Sandbox aggregator, so the guide is
verified against the very import list it tells readers to copy. Locally, copy that aggregator's
`<Import>` lines into `ci/wiki-snippets/Imports.props` yourself.

## Steering it from the wiki

Both markers are HTML comments and do not render.

| Marker | Effect |
|---|---|
| `<!-- verify:context ... -->` | page-level setup prepended to every snippet on that page |
| `<!-- verify:skip reason -->` | before a block that cannot compile. **The reason is required.** |

Context exists because most blocks are **fragments by design** — they use `store` and `product`
because the prose just introduced them. Without it, a guide written for people would have to be
written for the compiler. Typed nulls (`JwtTokenProvider provider = null!;`) are the usual shape: the
compiler still checks every call signature, which is the drift worth catching, without needing
runnable setup.

Skip only when a block references something the **reader** supplies. Four do today.

## What it does and does not catch

**Does:** renamed types, changed signatures, moved namespaces, required parameters, wrong base types.
On its first run it found six such errors, including a migration example written against an
`ISchemaBuilder.AlterCollection` that does not exist.

**Does not:** whether the prose is true, whether the code does what the text claims, or whether
anything is out of date but still compiles. It is a guard, not a proof.
