# The ribbon tokens were hand-edited into generated CSS

## Context

Found starting TASK-751. `Birko.Web.Components/css/tokens.css` is generated byte for byte from
`Birko.DesignTokens/tokens.json` (its banner says so). TASK-730's divider follow-up and TASK-747 edited `tokens.css`
directly: `--b-ribbon-group-gap` became `var(--b-space-lg)` and 23 `--b-ribbon-*` tokens were added. The next
`generate` would have silently deleted all of them (the third time this has happened, see Birko.DesignTokens/CLAUDE.md),
and `dotnet run --project Birko.DesignTokens -- verify` exited 1: "DRIFT: tokens.css differs from tokens.json
regeneration". Released in v0.1.14 to v0.1.17 with the CSS correct and the source stale.

## Acceptance criteria

- [x] `tokens.json` holds the ribbon tokens; `verify` passes on all 5 CSS and 6 AXAML files
- [x] The web CSS is unchanged

## Human test plan

N/A — fully covered by automated tests (`verify`, CssParityTests).

## Outcome (2026-10-23)

- Recovered as Birko.DesignTokens/CLAUDE.md prescribes: `extract` (it folded the live CSS back into `tokens.json` and
  reported all 5 sheets round-trip clean), then `generate`, then `verify`: "OK — all 5 CSS + 6 AXAML file(s) match
  tokens.json exactly".
- The web CSS came out identical (only line endings differed, so those files were restored and are not in the commit).
- The Avalonia themes gain the 21 sized ribbon tokens as `BRibbon*` resources, which TASK-763 will use. The desktop
  ribbon reads `BRibbonGroupGap`, so its gap between groups is now 16px, as on the web (24px before); part of
  TASK-751's parity. `--b-ribbon-popup-max-height` (60vh) has no AXAML form and is listed as deferred.
- **Gate.** Birko.DesignTokens.Tests 59/59; Birko.Xaml.Avalonia.Tests 209/209.
- Lesson: a ribbon size token goes into `tokens.json`, then `generate`. TASK-763 adds the desktop side the same way.
