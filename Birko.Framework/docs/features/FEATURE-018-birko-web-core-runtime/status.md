## What can be tested now

All four are shipped and exercisable in any app built on `Birko.Web.Core`:

- A request against a network that has gone away **gives up** instead of leaving the app waiting forever,
  and a response whose body stalls mid-transfer is reported as a failure rather than a success.
- A queued write replayed after the connection returns is **not applied twice** when the server had in fact
  already accepted it.
- Combining an endpoint that already carries a query string with extra parameters produces a valid URL.
- A list that is empty because nothing has ever synced is **distinguishable** from a list that is empty
  because there genuinely is nothing — so a screen can say which.
